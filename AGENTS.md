# AGENTS.md

## Architecture

- `public/` — static frontend (`index.html`, `styles.css`, `app.js`). No build step or framework; `app.js` fetches
  the API and re-renders the DOM directly.
- `netlify/functions/` — Netlify Functions acting as the REST API:
  - `products.mts` → `/api/products` (GET, POST, PUT?id=, DELETE?id=)
  - `clients.mts` → `/api/clients` (GET, POST, PUT?id=, DELETE?id=)
  - `sales.mts` → `/api/sales` (GET, POST, PUT?id=, PUT?id=&action=payment, DELETE?id=)
- `db/schema.ts` — Drizzle schema (`products`, `clients`, `sales` tables). `db/index.ts` exports the Drizzle client
  wired to Netlify Database.
- `netlify/database/migrations/` — SQL migrations generated by drizzle-kit; applied automatically on deploy.

## Conventions

- Sale line items and payment history are stored as JSONB columns on `sales` (`items`, `history`) rather than
  normalized child tables, since they are always read/written as a whole with the parent sale.
- Stock is decremented/restored server-side inside the `sales` function whenever a sale is created, edited, or
  deleted — the frontend never mutates `products.stock` directly.
- Money columns are Postgres `numeric`, so the API returns them as strings; the frontend parses them to `number`
  right after fetching (see `cargarDatos()` in `app.js`).

## Non-obvious decisions

- No frontend framework/build step was introduced — the original single-file prototype's UI/UX was preserved and
  only the persistence layer moved from `localStorage` to Netlify Database, since business data (inventory, client
  records, sales) must not live only in a single browser's local storage.
- Any schema change in `db/schema.ts` must be followed by `npx drizzle-kit generate --name <description>` to produce
  a migration — without it the database schema will not change.
